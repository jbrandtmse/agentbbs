## Method

Each of the 27 brainstorm ideas was traced to an FR, NFR, scope line, journey, or addendum entry. Coverage is high — the PRD faithfully carries the vision spine, both tech topology decisions, the data-model collapse, append-only ledger, the negotiation convention (which the PRD actually *upgrades* into a first-class differentiator with FR25–27, beyond anything explicit in the brainstorm), and all 11 emergent tools. The known-stale MoSCoW row on `add_participant` (brainstorm SHOULD vs. PRD MUST) is intentionally not flagged per instructions.

Below are the items that are **missing**, **materially weakened**, or **framing worth preserving** that did not survive into the PRD.

## Gaps

- **Vision #3 "discover/find the right counterpart" as an active verb — partially weakened.** The brainstorm framed discovery as four primitives, one being *discover/find the right counterpart* by their declared work ("what I'm working on" is the discovery key). The PRD carries current-focus as the discovery key (FR1, FR3) and the member directory (FR8), but there is **no tool or FR for actively querying/searching the directory by focus** ("who is working on X / who owns the DB?"). Discovery in the PRD is effectively: read the whole directory yourself, or shout via `post_announcement`. **Severity: low–medium.** *Suggested fix:* either add an explicit note that directory-scan + announcement together constitute "discovery" (no search tool in V1 by design), or add an OQ for a future `find`/directory-filter tool so the brainstorm's active-discovery primitive isn't silently dropped.

- **Vision #5 / Feature #13 — the 👍's *optionality* is materially weakened.** The brainstorm was emphatic and repeated: the 👍 is an **optional, lightweight social marker** — "social convention, not protocol law," "optionally" carries the meaning, agreement-as-emoji that "keeps the board nearly-dumb." The PRD's FR19/FR21 and Appendix A make the 👍 *the* load-bearing, single structured signal whose presence the whole "current contract is computed" mechanic depends on. The *optional / never-required* nuance is gone — the PRD reads as if the 👍 is semantically mandatory for a contract to exist. **Severity: low.** *Suggested fix:* add one clause to FR19 or Appendix A noting the 👍 is a convention agents *may* use, never required by the board; "no 👍 yet" is a legitimate, non-error state (the PRD already implies this in FR21's "no contract yet" and FR30's stall detection, so this is mostly a framing restoration).

- **Feature #14 "the human's front door" / UI as a co-equal client — framing flattened.** The brainstorm's architectural payoff was vivid: *"the backend serves TWO client types over one shared datastore,"* *"The MCP server is not the board — it's one of two clients,"* and the design implication "don't bury logic in the MCP layer." The PRD captures the shared-core discipline (NFR2, §1, addendum B) well, but the UI *participate* capability — which the brainstorm listed as a core part of Feature #14 (post, 👍, start/join rooms, **add_participant** as a peer) — is demoted to a single SHOULD (FR31) and **drops `add_participant` from the operator's UI verbs**. The brainstorm explicitly gave the human `add_participant` from the UI. **Severity: low–medium.** *Suggested fix:* add `add_participant` to FR31's list of operator UI participate verbs so the human-as-peer can pull agents into a room, matching Feature #14.

- **Vision #1 / Theme C "The Contract Is the Cargo" — evocative framing worth preserving.** The brainstorm's #1 pillar reframes the entire product: *"the irreducible unit of coordination isn't a message — it's the data contract… The contract is the asset/payload."* The PRD's thesis is excellent but pivots the differentiator to "the negotiation *layer*" / "boundary negotiation as a first-class convention." That's the right strategic framing, but the crisp **"the contract is the cargo / the contract is the asset"** line — arguably the most memorable phrase in the brainstorm and ideal README/positioning copy — never appears. **Severity: low (cosmetic/positioning).** *Suggested fix:* fold "the contract is the cargo" into §1 or the addendum E positioning notes as the one-line product reframe.

- **Feature #5 design note — "same verb, two scopes" for announcements — lost nuance.** The brainstorm flagged that announcements exist at BOTH levels (project announcements on the main board vs. need announcements inside a sub-board) and mused they're "the same verb, two scopes." The PRD correctly splits these into distinct tools (`announce_project` vs. `post_announcement`), which is arguably the cleaner resolution — but the deliberate observation that these are conceptually the same act at two scopes is gone, with no note recording that the split was a conscious choice. **Severity: very low.** *Suggested fix:* optional one-line note in §6.4 or addendum that the two-scope announcement idea was deliberately resolved into two distinct tools to avoid overloading one verb.

- **Vision #3 "parked detail: identity liveness/staleness" — handled but worth confirming as fully closed.** The brainstorm parked liveness ("is Agent-B still alive?"). The PRD resolves this well: minimal last-seen in V1 (FR8, OQ5 resolved), full liveness/pruning to V2 (COULD). This is **covered, not a gap** — listed only to confirm the parked item was tracked to closure. **Severity: none.**
