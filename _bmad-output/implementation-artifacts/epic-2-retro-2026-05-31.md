None were padding.
- **Architecture held under the epic's hardest requirement.** 2.2's atomic cross-process handle uniqueness via the data-described `appendGuarded` + `BEGIN IMMEDIATE` check-then-insert, proven by a real N=8 OS-process race (exactly one winner). Kept board vocabulary out of the ledger schema and stayed V2-HTTP-portable.
- **Forward-design compounded.** The 2.2 dev pre-wired the identity projection (`IDENTITY_EVENT_TYPES` + reducer markers) so 2.4 (`identity.focus_updated`) and 2.5 (`identity.seen`) were small, additive fold edits. The reusable primitives built this epic — `appendGuarded`, the `NO_IDENTITY` code, the session holder — are exactly what Epic 3 (`PROJECT_EXISTS`, `join_board`, `announce_project`) consumes.
- **Lead stdio smokes proved the production path, not just the tiers.** Every identity tool was exercised over a real spawned stdio server with an out-of-band ledger assertion (e.g. login wrote nothing → `maxSeq` unchanged; focus update retained the old row; `last_seen` has no stored column).

## Challenges / Lessons

- **[PRIMARY] Monorepo build-ordering papercut.** Cross-package tests resolve `@agentbbs/core` via its built `dist/`, so a new `core` export consumed by `mcp-server` produces a false-red `INTERNAL_ERROR` until `pnpm run build` runs. Surfaced explicitly in 2.4, present all epic (the lead rebuilt before every smoke for the same reason). → **codified as Rule 2** (with the preferred permanent fix — Vitest `src` alias or `pretest` build — tracked in `deferred-work.md`).
- **`boundary-enforcement.test.ts` cold-start flake.** A 5000ms ESLint timeout under full-suite parallel load (green in isolation / on warm re-run). Hit during the 2.2 and 2.4 gates. Narrow one-off (bump that one test's timeout) → stays tracked in `deferred-work.md`, NOT codified.
- **Orphan-append wart (class-deferred).** `recordSeen` and `updateFocus` both append an event before the fail-loud read-back guard throws on an unregistered handle (unreachable in V1 — both only ever receive a registered session handle). Deferred as a class so the guard-before-append fix is applied to both symmetrically → `deferred-work.md`, NOT codified.
- **`login` "writes nothing" vs presence.** A genuine design fork resolved cleanly: the architecture names the `last_seen` triggers as `check`/post (future epics), so `login` stays append-free (2.3) and the `identity.seen` primitive (2.5) ships as plumbing with a Rule 1 "no consumer yet" declaration (first consumer Story 6.1 `check`).
