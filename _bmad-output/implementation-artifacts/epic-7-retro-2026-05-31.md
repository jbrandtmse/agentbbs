## Challenges / Lessons

- **[PRIMARY] An agent-CONSUMED asset (the prompt snippet) raises the bar for doc-vs-code drift: a wrong tool name becomes a runtime failure an agent hits.** The Epic 8 install kit inlines `agent-prompt-snippet.md` VERBATIM into agents' system prompts — so a phantom tool in the snippet is not a cosmetic doc bug, it's an instruction an agent tries to execute and fails on. The QA-added "no phantom tools" guard (scoped to the inlined sentinel block, pinned to the live tool set) is the right enforcement. This generalizes: any doc/asset a machine consumes (the tool contract agents read, the protocol they follow, the prompt they're configured with) must be code-pinned, not just prose-reviewed. → Rule 10.
- **The seed introduced the project's SECOND piece of non-event state-ish surface — but stayed append-only.** Unlike the Epic-6 `cursors` table (the one mutable store), the protocol seed is pure append (idempotent via `appendGuarded`), so it did NOT need a carve-out — it's just a system-authored set of events on a reserved board. Worth noting the distinction: the cursor is mutable bookkeeping (carve-out); the seed is institutional memory (normal events, exported, reconstructable on import). The reviewer confirmed the seed touches only `events`, never `cursors`.
- **Content-guard parse robustness is a recurring small cost.** Each content-guard test parses a markdown doc (a sentinel block, a table column). The dev/QA used sentinel-delimited blocks (`AGENTBBS-*:BEGIN/END`) + section-scoped table parses to keep it robust (no off-by-one, no prose false-positives). Minor, but a pattern to keep consistent (the sentinel-block convention is now used by the tool contract + the snippet) — folded into Rule 10's guidance.

## Rules to Codify (meta-rule step)

One general-pattern lesson rose to class-of-issues shape and is codified in `.claude/rules/project-rules.md` (the file had Rules 1–9, so this lands as **Rule 10**):

- **Rule 10 — An open-source-facing or agent-CONSUMED doc/asset must ship with a content-guard test that pins its machine-relevant claims to the code's source of truth, mutation-tested non-vacuous.** Motivated by Epic 7's tool contract (7.0), protocol doc (7.1), and prompt snippet (7.3) — each pins its claims (tool names ↔ `listTools()`, error codes ↔ `BOARD_ERROR_CODES`, events ↔ `EVENT_TYPES`, the four moves, the FR21 semantic, the snippet's referenced tools ↔ the live tool set) to the code, parsed from a sentinel-delimited block, and the QA stage caught a real drift gap in 3 of the 4. Prevents the class of a doc/asset silently lying about the code — which is worse than no doc, and (for an agent-consumed asset the install kit inlines into prompts) becomes a runtime failure an agent hits.
