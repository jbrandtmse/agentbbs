The rule codified one epic ago immediately prevented three would-be confused debugging loops. Codifying retro lessons works.
- **The derived-state-by-query architecture made the marquee FR21 contract trivially correct.** `currentContract` is a fresh query over the live-👍 state every call, so AC #2's "revert on retraction" needed ZERO special logic — recomputation naturally yields the next-highest live-👍'd message. No stored contract, no revert branch, no bug surface. The append-only/derived discipline (held since Epic 1) paid its biggest dividend here: the hardest-sounding AC was the easiest to implement correctly.
- **The build/typecheck gate caught two issues the Vitest `src`-alias hid (5.1 `Buffer` TS2591, 5.3 named-interface cast TS2352).** This is exactly the residual the Story 3.0 alias + `project-rules.md` §2 warned about: tests run against `src` (looser), the SHIPPED `dist` is validated only at build/typecheck. Both were caught at the gate, never reached a commit. The honest-order gate (`build` → `typecheck` before trusting green tests) is doing its job.
- **QA continued to add the one guarantee the sequential dev tests can't reach.** 5.2's forked react-race (8 OS processes → live-set convergence + same-actor latest-wins-by-seq determinism, per the new Rule 5). 5.3's mutation-tested selection semantics (temporarily broke `contract.ts` to PROVE the "highest-seq-not-most-reactors" and ≥3-level-reversion tests discriminate, then reverted byte-identically). - **Clean, compounding reuse.** 5.3 (`currentContract`) is a thin filter over 5.2's `reactions` over 4.4's `roomMessages` over 4.1's rooms projection — four epics of folds composing without a reshape. 0 HIGH/MED and 0 rework for the second consecutive epic.

## Challenges / Lessons

- **[PRIMARY] An epics.md AC (5.1 "non-participant → NOT_A_MEMBER") CONTRADICTED an already-implemented earlier-story design (4.3 `reply` GRANTS participation — "acting = joining").** The planning doc was written before 4.3's grant-on-act semantics were finalized, so 5.1's AC literally asked for a gate that would break Epic 4's open-negotiation property. The lead reconciled it explicitly (documented in 5.1 Dev Notes: the room-MESSAGE post `reply` grants and has no `NOT_A_MEMBER`; the gate the AC references is `post_announcement`'s sub-board gate, reaffirmed) rather than blindly implementing the contradictory AC. → **codified as Rule 8** (when a story AC contradicts an earlier story's IMPLEMENTED design, reconcile explicitly — don't blindly implement the new AC over the established reality). This is a recurring risk for BMad's predates-implementation planning docs.
- **QA's mutation-testing of its own new tests (5.3) is an exemplary anti-vacuous-test practice worth mandating for high-stakes semantics.** The 5.3 QA temporarily mutated `contract.ts` to a wrong selector and confirmed its added tests went RED — proving they discriminate, not merely pass. The Story 1.3 retro-era risk (vacuous type assertions that pass regardless of correctness) is the same class. → **codified as Rule 7** (for a test pinning an easy-to-get-wrong SELECTION/ORDERING/PRECEDENCE semantic of a marquee feature, mutation-test it once to confirm non-vacuity, then revert byte-identically).
- **Tool/test-count drift in tracking docs recurred (5.3: 572 vs 575, 16+5+6 vs 19+4+6).** Each reviewer reconciled it against the live gate. Harmless (the gate is truth) but persistent — the per-stage `tests_added` in the cycle log is the durable record; the prose counts drift. Not rule-worthy (same observation as the Epic 4 retro); the cycle log is the source of truth.

## Rules to Codify (meta-rule step)

Two general-pattern lessons rose to class-of-bugs shape and are codified in `.claude/rules/project-rules.md` (the file had Rules 1–6, so these land as **Rules 7, 8**):

- **Rule 7 — Mutation-test a high-stakes semantic test to confirm it is not vacuous.** Motivated by Story 5.3's QA temporarily breaking `contract.ts` to prove the "highest-seq-not-most-reactors" + ≥3-level-reversion tests discriminate, then reverting byte-identically. Prevents the class of vacuous/tautological tests that pass regardless of correctness (the Story 1.3 vacuous-type-assertion class). Apply to the core SELECTION/ORDERING/PRECEDENCE logic of a marquee feature; not every test.
- **Rule 8 — When a story's AC contradicts an earlier story's IMPLEMENTED design, reconcile explicitly — don't blindly implement the new AC over the established reality.** Motivated by Story 5.1's epics.md "non-participant → NOT_A_MEMBER" AC contradicting Story 4.3's already-shipped "`reply` grants participation". Document the resolution in the story Dev Notes and surface it. Prevents the class of a later story silently breaking an earlier story's design because a predates-implementation planning doc said so.
