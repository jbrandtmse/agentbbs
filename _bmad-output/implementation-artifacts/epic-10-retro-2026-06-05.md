## What was rougher — the sharp lesson

**Three real defects, every one real-browser-only, every one invisible to the automated tier — surfaced only by a human driving the actual extension:**

1. **Room webview stuck on "opening room…"** — React **StrictMode**'s simulated unmount/remount disposed the postMessage bridge's `window` 'message' listener (created in render), and it was never recreated (ref not nulled; `acquireVsCodeApi()` can't re-run). The fake-bridge unit tests inject the `Bridge` interface directly; the in-host probe called `dispatchRequest` directly — **neither mounts the real bundle**, so neither exercised the StrictMode lifecycle.
2. **Every message body rendered EMPTY** — the byte-shared `ui-shared` `MarkdownView` runs Shiki as WebAssembly; the strict 10.5 CSP (`script-src 'nonce-…'`, no `wasm-unsafe-eval`) blocked `WebAssembly.instantiate` → `renderMarkdown` never resolved. **happy-dom does not enforce CSP**, so no shim test could see it.
3. **DB path not configurable in-plugin** — env-var-only discovery + an unreliable `process.cwd()` default (the VS Code install dir, not the workspace, for an installed extension).

Root cause (team consensus): **the webview's automated coverage tested the data path, not the rendered surface.** The Rule-14 integrated probe was data-bearing (it drove the panel managers + `dispatchRequest`), and the DOM tier was happy-dom — between them they never mounted the real bundle in a sandbox that enforces CSP + runs the live StrictMode message round-trip. That space is exactly where the three defects lived. The manual real-host smoke is the only instrument that saw them.

A secondary tail: the `wasm-unsafe-eval` fix updated the UNIT content-guards (precise-token) but missed the **in-host probe's** assertion, which false-RED'd on the now-correct CSP (`wasm-unsafe-eval` contains the substring `unsafe-eval`). One token, four guard sites, one missed.

A process note: Story 10.3's *aggregate* gate (typecheck/format) had latent drift that a `pnpm test`-only check didn't catch; the 10.4 dev found + fixed it. The lead now runs the FULL aggregate gate (build/typecheck/lint/format + test) at every smoke.

## Rules codified (Rule-1 step) → `.claude/rules/project-rules.md`

- **Rule 17** — A webview/iframe-client smoke must MOUNT the real bundle in the real host and exercise the live message round-trip + content render; a dispatch-direct probe and a DOM-shim test are necessary but NOT sufficient (happy-dom ignores CSP; the direct probe bypasses the postMessage listener + the StrictMode mount lifecycle). Sharpens Rule 12, extends Rule 16 to the embedded-client transport seam.
- **Rule 18** — A substring-based forbid guard needs precise-token matching when a legitimate longer token contains the forbidden substring (`wasm-unsafe-eval` ⊃ `unsafe-eval`); and adding such a token means updating EVERY guard that checks it (unit AND in-host probe AND runner), not just one.
- **Rule 19** — A thin client mounting a byte-shared component INHERITS that component's runtime requirements (WASM/network/workers/fonts); verify them against the new host's sandbox (CSP/sandbox/bundle-mode) at integration, or the shared component fails silently. Extends Rule 13.
