## What went well

- **The whole backup/restore loop works end-to-end against the real bins.** Lead smokes ran `agentbbs export` → `agentbbs import` → re-export across real SQLite boards: 19-event archives round-tripped with byte-identical `seq`/`type`/`actor`/`payload`, non-empty boards correctly rejected, a real 1.88 MB node:sqlite-only `.vsix` produced, 4 leak-free npm tarballs (`workspace:*` rewritten, cli ships `web-dist/` 304 files).
- **The cursor read-state design call (11.2) was caught at authoring time, not at the round-trip.** Cursors are the append-invariant carve-out — NOT derivable from the event stream — so the archive had to capture them explicitly or 11.4's `cursors` comparison would silently fail. Reconciled in writing (Rule 8) and confirmed lossless by 11.4.
- **Two stale planning ACs reconciled cleanly (Rule 8).** 11.5's "ABI-matched better-sqlite3 prebuilds" was MOOT (the extension ships on node:sqlite, zero better-sqlite3 in the bundle — Epic-10-proven), and the "12-tool surface" was corrected to the shipped 17. Both resolved on purpose, documented, never silently bolted on.
- **The deferred-cleanup story (11.0) paid for itself immediately.** Stabilizing the Windows `seed-protocol-race` EPERM + the Shiki full-suite flake gave every subsequent Epic-11 story a reliably-green gate to smoke against — exactly its purpose.

## What was rougher — the sharp lessons (all caught UPSTREAM of smoke)

Notably, every defect this epic was caught by QA or CR — smoke caught zero escapes. That's the pyramid working, but the catches are the lessons:

1. **11.2 — the dev's "gate green" claim was false.** The closing summary said "lint 0 / format clean"; the gate was actually RED on a rest-sibling destructure-drop (`no-unused-vars`) + an over-width prettier line. CR re-ran the FULL gate and caught it. → **Rule 20.**
2. **11.5 — the README rewrite shipped 97 mojibake sequences + a BOM.** The Rule-10 content-guard was correctly green (every ASCII machine token survived byte-intact) but is structurally blind to prose-glyph corruption. CR caught it out-of-band. → **Rule 21.**
3. **11.4 — the fidelity seed had a vacuous category.** Zero proto-rooms meant `listAnnouncements` compared `[]===[]` — a green-but-meaningless assertion. QA strengthened the seed + added per-category non-emptiness guards. (Reinforces Rule 7.)
4. **11.5 — the README content-guard had a call-form blind spot.** It pinned only the sentinel block; a bin rename in the visible copy-paste config fence passed green. QA closed it with visible-surface assertions. (Reinforces Rule 18 / the Epic-8 call-form lesson.)

## Rules codified (Rule-1 step) → `.claude/rules/project-rules.md`

Both ratified by the Project Lead in this retro:

- **Rule 20** — A "gate is green" claim is unverified until INDEPENDENTLY re-run, and the gate is lint + typecheck + build + test + format, not just test. (11.2)
- **Rule 21** — A doc/prose rewrite must be encoding-verified out-of-band; a machine-token content-guard is blind to multibyte-glyph corruption (mojibake/BOM). (11.5)

Lessons 3 and 4 were judged already-covered by Rules 7 (mutation non-vacuity) and 18 (call-form precise matching) respectively — reinforced in this retro, not re-codified.
