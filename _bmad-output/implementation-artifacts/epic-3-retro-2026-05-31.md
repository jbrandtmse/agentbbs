## Challenges / Lessons

- **[PRIMARY] The `src` alias fixed *tests*, not *typecheck* or *forked workers*.** `pnpm run typecheck` (`tsc`) still resolves `@agentbbs/core` via `dist/*.d.ts`, so every dev/QA/CR stage hit a transient `TS2305` false-red until `pnpm run build`. The forked cross-process tests (`register-race`/`concurrency`) likewise resolve via `dist` in real child processes — surfaced sharply by my own 3.0 smoke (deleting `core/dist` killed the workers `ERR_MODULE_NOT_FOUND`). I patched `project-rules.md` §2 with the forked-worker caveat. → **logged in `deferred-work.md` (E3-typecheck-dist) for the Epic 4 Story 4.0 triage; NOT codified** (it is the same build-ordering class as the now-superseded Rule 2, partially residual, and the user opted to keep the cadence).
- **MCP tool names are set implicitly, story-by-story, not ratified against a contract.** `list_members` (vs `get_board_directory`), `{ projects }`/`{ members }` envelopes — reasonable and consistent, but the agent-facing contract is being frozen one story at a time. → **logged (E3-tool-names) for Epic 7's `mcp-tool-contract.md` (or sooner if the user wants it frozen before Epic 4's post tools).**
- **3.0 carried two new LOWs** (3.0-a: the cross-package proof fixture is a permanent public `core` export — now redundant given 3.1's real exports are the standing alias proof; 3.0-b: guard-before-append doubles the happy-path read on the `recordSeen` hot path). Both tracked; 3.0-a is a trivial cleanup, 3.0-b is a Story-6.1 measurement item.
