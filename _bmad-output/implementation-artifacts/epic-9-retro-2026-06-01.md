## What went well

- **Mutation-tested marquee semantics carried from the agent epics into a UI epic.** Every load-bearing UI semantic was mutation-tested non-vacuous AND independently re-verified by both QA and code review: FR21 computed agreed mark (highest-seq-live-👍, NOT most-reactors) at both the host-ledger and UI-mapping layers; NEEDS-YOU explicit-escalation-only (never time-based); the NFR12 inert pipeline; optimistic de-dup; the 👍-revert no-count-drift; the no-modal-anywhere invariant; the live-region coalesce. Rules 7 + 10 translated cleanly to React/host code.
- **Real-Chrome smokes earned their keep.** They proved what happy-dom structurally can't: `var()` token flip actually painting, NFR12 zero content-triggered network + canary-never-fires in a real browser, real `EventSource` SSE delta delivery (Mode A live fold), the agreed mark moving in the DOM, the Mode A→B peer flip via a real `reply`, and `○ reconnecting…` inline with no modal.
- **Honest contract discipline.** 9.5 added the display `created_at` HOST-LAYER-ONLY (core + ratified MCP wire byte-identical, drift-guards green); 9.6 kept `NO_OPERATOR` a host-surface code outside the closed `BOARD_ERROR_CODES`. The agent-facing contract from Epics 1–8 was never mutated to serve the UI.
- **Rule-8 reconciliations done on purpose, in writing.** 9.7 mapped the join-gate composer onto the board's grant-on-act model (no standalone room-join op invented); 9.8 made tab-close a VIEW-only action (the board has no leave op); the operator posts via the SAME core `reply` agents use — no backdoor.

## What was rougher / lessons

- **Per-package test-runner false failures.** Three reviewers (9.6/9.9/9.10) nearly mis-read `.tsx` DOM tests as failing because `npx vitest` inside `apps/web` bypasses the root `ui-shared-dom` happy-dom project. The canonical `pnpm test` was green every time. → **Rule 12** (canonical root gate + ground-truth check).
- **DOM-shim limits.** happy-dom's incomplete `var()`/CSP/network handling forced several "assert the custom property at its declaration site" workarounds and made the real-browser smoke load-bearing, not optional. → **Rule 12.**
- **The timestamp gap (9.5) and the join semantics (9.7)** were planning-vs-shipped-reality reconciliations that needed a deliberate decision rather than mechanical AC implementation. Handled correctly (Rule 8) but each cost a design pass. → reinforced in **Rule 13.**
- **The Shiki warmup flake (9.5)** turned out to be a deterministic ` ```ts ` lang-alias miss already fixed in-changeset, not a race — correctly investigated (not normalized) and deferred as a LOW with analysis.

## Rules codified (Rule 1 step)

- **Rule 12** — A UI/web story's per-story smoke MUST drive a REAL browser; DOM-shim tests are necessary but not sufficient; in a monorepo with a root test-projects config the canonical gate is the root test command (not per-package runs).
- **Rule 13** — A thin client (UI/host/extension) adds only CLIENT-LAYER fields and maps affordances to EXISTING board ops — never mutates the ratified agent contract, never fabricates a board op or a client backdoor; a deferred affordance is gated or recorded as an inert stub. (Extends Rules 8 + 10 to client surfaces; the rule the VS Code extension will lean on most.)
